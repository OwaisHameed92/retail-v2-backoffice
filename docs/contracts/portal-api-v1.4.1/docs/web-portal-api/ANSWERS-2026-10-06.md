## Purane khule sawal

### 1. Doosra till main till se kaise judta hai? (aap ka Till 2 standalone ban gaya)

Jawab: **"Join" wizard ke doosre page par hai, aur sync key doosre till par nahi lagti** — aap ki baat sahi hai.

**Naya install (sahi raasta):**
1. **Main till:** Admin → Settings → **Tills** → "This PC" = **Main till**. Wahan **Shop code** dikhta hai ("Type this
   code on each extra till"). Zaroorat ho to "Allow through Windows Firewall". Main till ke paas licence key honi
   chahiye — warna woh koi till nahi leta.
2. **Till 2 wizard:** Step 1 = Till 2 ki **apni** licence key (har till ki alag key). Step 2 (shop type page) ke
   upar: "Is this an extra till for a shop that already uses SSPOS?" → **Connect to the main till** → network par
   mile main tills ki list (na mile to main till ka PC naam / IP) → shop code → **Connect**
   (`src/SSPOS.Desktop/Features/FirstRun/FirstRunViewModel.ExtraTill.cs`). Staff, settings aur products copy hote
   hain, wizard wahin khatam: **shop type, shop details, owner PIN nahi**. Sign in main till wale PIN se.

**Jo Till 2 pehle hi standalone set up ho chuka hai:** Till 2 par Admin → Settings → **Tills** → **Extra till** →
shop code → Connect (`src/SSPOS.Client/TillLink.cs`). Is ke baad:
- Till 2 **kabhi sync nahi karta** (`SyncSenderGate.cs`: secondary till sync refuse karta hai); sync key box
  greyed: "Enter the sync key on the main till".
- Till 2 ke apne database ke company/branch ids **re-key nahi hote** (invariants rule 5) — magar ab woh jo bhi
  trade karta hai main till ke database mein likha jata hai aur **main till ke push** mein aata hai, main till ke
  `companyId` / `branchId` ke saath aur `registerId` = Till 2 ka apna register id. Pehli join par main till us id se
  aik `Register` row (code jaise `T02`) bana kar push karta hai (`StoreJoinService.cs`). Detail: doc §2 point 2.

**Portal ko kya karna hai:**
- Till 2 ne standalone hote hue jo rows apni company/branch ke ids se bheji thin (Company, Branch, Register, User,
  Setting…) — woh test/orphan company hai; **portal par alag rakh kar mita dein**, main shop mein merge na karein.
- Agar Till 2 ko licence reply mein `apiKey` diya tha to us branch key ko **revoke** kar dein (Till 2 kabhi wapas
  "Only till" bana to warna phir apni ids se sync shuru kar dega).
- Aage ke liye: extra till ki key **shop ke wahi `companyId` / `branchId`** ke saath banayein (`KEY-CARRIES-SHOP.md`).
  `licence/activate` / `validate` reply mein top-level `companyId` / `branchId` **hamesha shop ke** bhejein, khaali
  nahi: till sirf us `apiKey` ko leta hai jis ka company/branch us ke apne database se milta ho, warna ignore karta
  hai (`PortalHubLinkWriter.cs`) — is tarah naya extra till join se pehle apni ids se sync shuru nahi karega.
- Per-till licence ko `installId` + key se pehchanein; extra till ke licence calls ke headers (`X-SSPOS-Company-Id`
  …) us ke apne database ke ids hote hain.

### 2. `devices/deactivate` — `tokenSha256` / `installCode` maang sakte hain?

**Aaj till kya bhejta hai** (`src/SSPOS.Infrastructure/Licensing/HttpLicencePortal.cs` → `DeactivateAsync`):
body `{registerId, installId, reason, note}` (`licensing/schemas/deactivate-request.schema.json`); headers
`X-SSPOS-Install-Id`, `X-SSPOS-Company-Id`, `X-SSPOS-Branch-Id`, `X-SSPOS-Register-Id`, `Idempotency-Key`, aur
`Authorization: Bearer <branch key>` **sirf jab** us till ke paas branch/sync key ho (yani main till jis par sync
laga ho). Per-till licence wala extra till koi bearer nahi bhejta. `tokenSha256` / `installCode` aaj **nahi**
jate (yeh `licence/validate` aur `licence/redeem` mein jate hain).

**Kya hum add karein ge:** haan — `devices/deactivate` body mein do **optional** fields `tokenSha256` (till ke
mojooda licence token ka SHA-256, validate jaisa) aur `installCode` add kar dein ge (§17.11 ke mutabiq additive).
Release number confirm kar ke `UPCOMING-CHANGES.md` mein likhein ge.

**Portal:** jab fields aayein to `tokenSha256` ko us install ko diye gaye token se milayein (na mile → 403); jab
tak purane tills (≤ 0.1.51) bina fields ke aate hain: bearer ho to us se, warna `installId` + `registerId` ka us
key se bound hona check karein — aur admin panel se Deactivate (§17.7 "Old PC dead?") hamesha mumkin rahe.

### 3. Portal se anonymised customer aaye — kya till baqi data khud saaf karta hai?

**Nahi.** Pull se aaya `Customer` aam row ki tarah likha jata hai (jo fields aap bhejein, `anonymisedAt` samait) —
koi handler nahi chalta, till par koi AuditLog nahi banta. Till ke apne "Anonymise" (`AnonymiseCustomerHandler.cs`)
bhi sirf `Customer` row saaf karta hai: `name` "Removed customer", `phone` / `email` / `address` / `cardNo` /
`notes` `""`, `dob` `null`, `isActive` false, `anonymisedAt` set (balance / points / creditLimit / tier rehte hain).
Jo **saaf nahi hota**: `CustomerOrder.customerName` / `customerPhone` / `customerEmail`, `EReceiptLog.address`,
`AccountPayDate.note`, `Consent` rows; `Sale.receiptJson` (completed sale immutable hai, invariants rule 5 — till
usay badal hi nahi sakta).

**Portal:** anonymise karte waqt Customer row mein upar wali sab values bhejein (khaas taur par `isActive: false`
aur `anonymisedAt`). Orders / e-receipt log branch-owned hain — portal unhein down na bheje; apni copy portal par
khud saaf karein. Till par in ko saaf karne ka step hum alag se dekh rahe hain (release mein aaya to UPCOMING mein
likhein ge).

### 4. Training-mode ki practice rows (0.1.44 tak) — har shop ki list

- Tool: **`tools/training-rows/training-rows.py`** (repo mein, 0.1.45 se). Aik till ke data folder
  (`%ProgramData%\SSPOS\data` ya us ki copy, jis mein `sspos.db` aur `sspos-training.db` hon) ko read-only khol kar
  har practice change ki CSV deta hai: `entity, entityId, op, version, atUtc, kind, sent, sentAt, ackedAt,
  portalReceivedAt, receiptNumber, total`. **`sent = yes`** wali rows hi portal tak pahunchi hain — sirf woh
  mitayein, receipt number se andaza na lagayein.
- Repo root wali `training-rows-this-till-2026-10-04.csv` sirf **hamare apne dev till** ki hai: 21 practice rows,
  sab `sent = no` — is till se portal par kuch nahi gaya.
- Doosri shops: jis till par `sspos-training.db` hi nahi, us ne kabhi training use nahi ki → kuch nahi. Baqi ke liye
  hum (ya dealer) us till ke data folder par yeh tool chala kar CSV aap ko bhejein ge. **Aap hamein un shops ki list
  dein** jo 0.1.45 se pehle sync kar rahi thin (`X-SSPOS-App-Version` ≤ 0.1.44 ke saath push) — sirf unhi ki zaroorat
  hai.
