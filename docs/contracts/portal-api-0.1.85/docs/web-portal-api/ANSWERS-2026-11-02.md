# Portal team ke liye — product pictures (`product-images`) ka jawab (2026-11-02)

Wa Alaikum Assalam,

Shukriya — proposal saaf hai aur hamare liye theek hai: teen calls (`PUT` / `DELETE sync/product-images/{productId}`,
`GET sync/product-images`), §3 headers, raw bytes, `X-SSPOS-Image-Sha256`, saat naye codes. Till par yeh ban raha hai;
pehla version **0.1.83** (rough date: **2026-11-06** tak stable par — release ke din confirm kar denge). Jab tak aap ka
switch off hai till har 501 `image.not_available` par chup chaap intezar karta hai, push / pull par koi asar nahi.

Neeche das sawalon ke jawab, phir do baatein jo aap ke §5 se thori mukhtalif hain.

**Q1 — body:** raw bytes + `Content-Type`, aap ka proposal hi. Multipart nahi chahiye.

**Q2 — limits:** 2 MB aur 2000 px theek hain; hamari tasveerein in se bohot choti hain.
- Haath se chuni tasveer ("choose a picture") folder mein aate hi seedhi ki jati hai (EXIF orientation) aur lambi side
  **512 px** tak choti, JPEG quality 85 (transparent ho to PNG). Original file ko till nahi chhoota.
- "Find pictures" / auto picture: Open Food Facts ki front picture (aam tor par ~400 px) ya web search ka thumbnail
  (**320 px**); sirf JPEG / PNG, 2 KB se 2,000,000 bytes.
- Phir bhi koi file 2 MB / 2000 px se bari ho (purani file, kisi ne haath se folder mein rakh di) to till us ki copy
  bhejta hai (lambi side ≤ 1200 px, JPEG 85) aur jo bheja us ka hash yaad rakhta hai; local file wahi rehti hai.
  16 px se choti tasveer nahi bhejta. WebP till kabhi nahi bhejta (JPEG / PNG hi).

**Q3 — tasveerein kahan se aati hain — public store par yeh ahem hai.** Teen sources:
1. **Shop ki apni** — product form par haath se chuni (USB, Downloads, phone photo).
2. **Open Food Facts** — barcode se pack ki front picture. Open database hai magar tasveerein CC BY-SA hain:
   public store par attribution / share-alike ki shart lagti hai.
3. **Web image search** — naam se (Bing thumbnail, safe-search strict). In ka copyright **maloom nahi**; till ke tile
   par chalta hai, public online store par nahi dikhana chahiye jab tak shop owner khud na kahe.

Is liye till har upload ke saath `X-SSPOS-Image-Source: own | library | found | unknown` bhejta hai (own = 1,
library = 2, found = 3, unknown = is version se pehle ki tasveer jis ka source till nahi janta). Hamari darkhwast:
store par default sirf `own` dikhayein; `library` attribution ke saath; `found` / `unknown` sirf jab owner portal par
"show found pictures" on kare. Header aap ke schema mein nahi hai — agar aap use na parhein to koi masla nahi, bas
ignore kar dein; agar parhein to schema mein optional add kar dein.

**Q4 — portal kya rakhta hai:** list call (§4.3) theek hai; `Product` payload mein `imageHash` ki zaroorat nahi.
Till khud har product ka yaad rakhta hai ke portal ne kaun sa hash qabool kiya (PUT ka `imageHash`), is liye list
sirf in moqon par chalti hai: upgrade ke baad pehli dafa, "Find pictures" dabane par, aur hafte mein aik dafa
(portal ki taraf koi tasveer gum ho gayi ho to pakar le). Page `max=200` (aik page = aik choti DB save; 100,000
products ≈ 500 calls, 2 second ke faasle se ≈ 17 minute).

**Q5 — capability:** list (ya kisi bhi call) par 501 kafi hai; `sync/hello` mein kuch nahi chahiye.

**Q6 — kaun sa till upload karta hai:** sirf branch ka **main till** (ya single till). Extra till kabhi upload nahi
karta — wahan chuni ya dhoondi tasveer bhi main till par save hoti hai. Kai shops wale business mein: `imagePath`
company-wide hai magar file aik hi PC par hoti hai, is liye **jis shop ke main till par file hai wahi bhejta hai**;
baqi shops ka till us product ko chhor deta hai.

**Q7 — hatana:** haan. Product form par "remove picture" `imagePath` khali karta hai → till `DELETE` bhejta hai.
Nayi tasveer hamesha nayi file name ke saath aati hai (purani file nahi badalti), is liye replace = naya `PUT`.
Product archive / delete par till kuch nahi bhejta (aap ke §4.2 ke mutabiq).

**Q8 — raftaar:** aik waqt mein aik call, **har 2 second mein zyada se zyada aik** (30 / minute — aap ki 60 ki
limit ka aadha, list aur delete ke liye jagah). Main till par sale khuli ho (cart mein item) to tasveerein ruk jati
hain; 429 / 503 par `Retry-After`, 5xx / no answer par 1 → 2 → 5 → 15 minute back-off. Aam din mein traffic na hone
ke barabar hai (naya product = aik tasveer). Pehli dafa bara catalogue: 5,000 tasveerein ≈ 3 ghante, ~20–60 KB har
aik — shop ki line par mehsoos nahi hota. Trading hours mein is se ahista karne ki zaroorat nahi.

**Q9 — merge:** till par merge mein jo product bachta hai us ki apni tasveer rehti hai; merge hone wale products
archive hote hain aur tasveer move nahi hoti. Portal archived products khud nahi dikhata, is liye koi call nahi.
Bachne wale ki tasveer na ho aur doosre ki ho — woh baad mein dekhein ge; is version mein nahi.

**Q10 — portal → till (§8):** haan, baad mein chahiye — `Product.imageUrl` + `imageHash` (optional, hub-owned
members, URL §18.9 ke mutabiq) alag table se behtar hai. Till file on demand download kar ke apna `imagePath`
bharega. Upload live hone ke baad is par alag se baat karein ge.

## Do baatein jo aap ke §5 se mukhtalif hain

1. **Sweep ka step 3 (portal par hai, till par nahi → `DELETE`) till nahi karta.** Kai shops wale business mein
   "is till par tasveer nahi" ka matlab aksar yeh hota hai ke file doosri shop ke main till par hai, ya is shop ne
   abhi taza `imagePath` pull nahi kiya. Is liye till **sirf woh tasveer DELETE karta hai jo usi ne bheji thi aur
   phir hata di**. Koi DELETE beech mein gum ho jaye to till dobara bhejta hai jab tak 200 na aaye.
2. **Product pehle, tasveer baad mein:** till tasveer tab bhejta hai jab us product ki `Product` row push mein
   acknowledge ho chuki ho, is liye `404 product.not_found` kam hi aana chahiye. Aaye to: 10 min → 1 ghanta →
   6 ghante → phir din mein aik dafa.

Baqi codes aap ke `tillDoes` ke mutabiq, aik farq ke saath: picture call par 401 / 403 / 426 aaye to **sirf tasveerein**
aik din rukti hain — till us se push / pull kabhi nahi rokta (key sach mein ghalat ho to push khud pakar leta hai aur
ruk jata hai, jaise pehle se hota hai; tab tasveerein bhi nahi jatin). Is tarah tasveeron ka koi jawab chalti shops ka
sync nahi rok sakta. List par 404 (portal par yeh calls abhi deploy hi nahi) = 501 jaisa: aik ghanta, phir din mein
aik dafa. 413 / 415 /
`image.dimensions` par aik dafa compliant JPEG copy (≤ 1200 px, 85) bhejta hai, phir bhi na chale to tasveer "refused";
`image.invalid` = "refused" — Sync status par product ke naam ke saath dikhta hai, nayi tasveer aane par hi dobara;
`image.hash_mismatch` / 429 / 503 / 5xx / timeout: baad mein wahi bytes; 501: `Retry-After` (kam se kam 1 ghanta),
phir din mein aik dafa.

**Aage:** 0.1.83 ke release ke din version aur date confirm kar denge; aap switch tab on karein.
