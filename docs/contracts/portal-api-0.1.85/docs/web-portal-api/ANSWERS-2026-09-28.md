# Portal team ke sawalon ke jawab — 2026-09-28 (package v1.3.3)

Wa Alaikum Assalam. Har jawab till ke code se check kiya gaya hai; docs bhi isi ke mutabiq theek kar di hain.

## 1. IDs (sab se zaroori) — till apni IDs rakhta hai

**Owner ka faisla (2026-09-28): till hamesha apni IDs rakhta hai** (pehli dafa chalne par banaye gaye ULIDs) aur
`licence/activate` mein `existingIds {companyId, branchId, registerId}` bhejta hai. Till aap ki IDs **kabhi nahi
leta** aur apna data kabhi re-key nahi karta. Sync ki har row par till ki IDs hongi.

Portal kaise milaye (`docs/web-portal-api.md` §17.3 step 3):
- **Naye customer ki pehli branch ka main till:** **adopt** — apni Company/Branch rows till ke `existingIds` par
  bana lein ya re-key kar lein (sign-up ke waqt un mein data nahi hota), ya aik mapping table rakhein.
- **Existing company ki doosri branch:** us ke main till ne apna alag `companyId` banaya hoga → use apni company
  par **alias** karein (`till companyId → aap ka companyId`, edge par translate, §17.8 wala qaida). Us ka `branchId`
  nayi branch ke taur par adopt karein.
- **Har key ko us branch se bind karein jis ke liye aap ne issue ki** (aap ke apne record se), `existingIds` se nahi.
  Till ko `installId` se pehchanein (har PC ka pakka) aur us ka `registerId` record karein.
- **Token** mein `companyId` / `branchId` = **aap ke customer ki IDs**, branch ki har key mein aik jaisi. Till sirf key
  se key milata hai (aik shop ke do tills aik hi company/branch bataein).

Mashwara: aik `id_map(kind, till_id, portal_id)` table — pehli branch par `till_id = portal_id`, baad ki branch ki
company par alias.

## 2. Do ki jagah aik code — haan

Till **pehle se** `licence/activate` aur `licence/validate` ke reply ke top level par `apiKey` (aur zaroorat ho to
`hubUrl`) parhta hai, save karta hai aur Cloud sync on kar deta hai. Is liye:
- Licence mein dashboard (`cloud_sync`) ho to branch ki **sync key `apiKey` mein bhej dein** → owner sirf licence key
  daalega. `hubUrl` sirf tab bhejein jab sync kisi aur host par ho (warna till ka built-in address chalega).
- Saath `companyId`/`branchId` bhejein to **till ki apni IDs ya khaali** honi chahiyein (doosri IDs wala link till
  nazar-andaz kar deta hai).
- **`devices/activate` mat banayein** — till use call nahi karta (§17.4 par note laga diya).
- `settingsBootstrap` is reply se nahi parha jata; settings `pull` se aayengi (v1.4).
- **Sync key** (Settings → Cloud sync → Connect) sirf us shop ke liye hai jo dashboard **baad mein** lagaye —
  `docs/web-portal-api/SIMPLE-SETUP.md`.

Schemas: `licence-activate-reply.schema.json` aur `validate-reply.schema.json` mein optional `apiKey` / `hubUrl` add.

## 4. §18.3 Admin panel — per-till model par update

Koi activation code nahi, koi seat nahi: har till ki aik key, "release key" (PC agli check par lock, key doosre PC
par chal sakti hai), re-issue, revoke; tills ki list = issued keys (bound PC, installCode, registerId, version,
last check-in). §18.3 dobara likh diya.

## 5. MySQL 8 — theek hai

Spec mein kuch bhi PostgreSQL ke baghair na-mumkin nahi. `DASHBOARD.md` ke akhir mein **MySQL 8 appendix**: types
(`DATETIME(6)` UTC, `DECIMAL`, `JSON`), `FILTER` → `SUM(CASE…)`, `ON CONFLICT` → `ON DUPLICATE KEY UPDATE` (version
ka field aakhir mein), `UTC_TIMESTAMP()`. **`trading_day` ingest par app code mein nikaalein** (Europe/London) —
`CONVERT_TZ` MySQL time-zone tables ke baghair chup-chaap NULL deta hai.

## 10. BranchPrice aur portal se Purchase Order — dono v1.4 mein (owner ka faisla)

Pehli shakal (pakki fields v1.4 mein):
- **BranchPrice:** portal ki row — `id, companyId, branchId, productId, price` (+ unit agar zaroori), `validFromUtc`,
  `validToUtc?`, `version`. Till `pull` se lagata hai; us branch par yeh product ki aam price se upar chalti hai.
- **Portal se PO:** portal branch ke liye draft `PurchaseOrder` + lines banata hai → us branch ke `pull` mein relay
  (transfers jaisa) → branch usi ke against maal receive (GRN) karti hai; receipt rows branch ki; aik hi PO do dafa
  relay ho to kuch nahi hota.

Test portal chalu hote hi base URL, public key aur test licence keys bhej dein — phir mil kar end-to-end test karenge.
