# Portal team ke liye — jawab (2026-10-06, doosra)

Wa Alaikum Assalam,

Shukriya — sab changes note kar liye. Q1 / Q3 / Q4 / Q6 / Q10, licence reply ke companyId / branchId, anonymise aur
training rows wala jawab hamare liye theek hai. Aap ki 4 baatein:

**1) Recall — har shop apna band kare: haan, yahi chahiye.**
Till **0.1.52** se close / reopen / wapsi har shop ki apni hai: naya branch-owned table `ProductRecallBranchState`
(us shop ki row; row nahi = us shop mein Open), aur `ProductRecall` ke `status`, `closedAt`, `closedByUserId`,
`note`, `returnedQty` ab `derivedColumns` hain — till inhein pull se kabhi nahi likhta. Aik shop ka shelf saaf hone
se doosri shop ka shelf saaf nahi hota, is liye aik shop ka close doosri shops tak **nahi** jana chahiye. Portal par
har shop ka haal `ProductRecallBranchState` rows (push mein aati hain, I/U) se dikhayein; jis shop ki row nahi, woh
Open hai. Poori row neeche bhejne ki zaroorat nahi (bhejein bhi to yeh paanch columns ignore hote hain).
Detail: `UPCOMING-CHANGES.md` ("`ProductRecall` per shop"), `web-portal-api.md` §10.1 aakhri paragraph.

**2) `device.token_mismatch` — shamil kar diya; naye fields till 0.1.53 se.**
- `licensing/samples/error-codes.json` mein `device.token_mismatch` (403, `devices/deactivate`) add hai; §17.7
  Errors mein bhi.
- Till **0.1.53** se `devices/deactivate` body mein optional `tokenSha256` (till ke paas jo licence key / token hai
  us ka SHA-256 hex, `validate` jaisa; koi na ho to `null`) aur `installCode` jate hain.
  `licensing/schemas/deactivate-request.schema.json`, sample `deactivate-request.main-till.json`.
- 403 `device.token_mismatch` par till yeh dikhata hai: "The licence server does not recognise this till's licence. Ask your dealer to
  deactivate it on the portal." (ya aap ka `message`), aur till par kuch nahi badalta.
- ≤ 0.1.52 wale tills yeh fields nahi bhejte — un ke liye pehle wala check.

**3) Extra till ke licence reply mein `apiKey`: mat bhejein (leave out / `null`).**
Branch ki sync key aik hai aur cloud sync main till karta hai; extra till ka data main till ke zariye jata hai, is
liye extra till ko key ki zaroorat nahi. Agar bhej bhi di (ab companyId / branchId shop ke hain) to till use branch
key ki jagah save kar leta hai — wahi key ho to koi farq nahi, magar purani ya galat key extra till par sync on kar
sakti hai. Is liye extra till (per-till licence wala `registerId` jo main till nahi) ke `activate` / `validate`
reply mein `apiKey` na bhejein; sirf main till ko.

**4) Till 2 — theek hai.** Extra till join karne ke baad us ki purani standalone rows test company mein reh jayengi;
go-live se pehle saaf karna sahi hai. Join ke baad Till 2 ka apna data main till ke zariye company ki asli ids ke
saath jayega.

fields). Poore din ka end-to-end test — din dukaan ke owner tay karenge, hum bata denge.
